# Hibiscus Club

Hibiscus Club is a single-player browser game inspired by early-2000s fashion-doll CD-ROMs. Dress the same character at two ages from head to toe, walk around the island helping its residents, spend the stars you earn in the island shop, rehearse a runway routine, and turn a favorite look into a downloadable postcard. The island map is the single home: its five buildings and the Dream House on the hill open rooms, and its five walk-in places let you explore on foot.

## Play locally

Use Node.js 16.14 or later and a modern browser. From the project directory, run the following command.

```sh
node serve.cjs
```

Open [Hibiscus Club on this computer](http://127.0.0.1:4173). The server binds to your computer’s loopback address. Stop it with Ctrl+C. If that port is busy, run `node serve.cjs 4180` and open the address printed in the terminal. The game uses bundled artwork and runs offline while the local server is running. There are no packages to install. Play statistics are switched off on a local address, so `serve.cjs` never sends anything.

You can also put the contents of `dist/` on a static web host. Serve the files together from the same origin so the browser can export postcard images.

## Deploy to Cloudflare Workers

`wrangler.jsonc` configures a Worker named `hibiscus-club`. The game is the static assets in `dist/`, and rooms use URL hashes, so no routing rules are needed. A small Worker script, `worker/index.js`, runs only for `/api/*` and `/stats` (the anonymous play statistics, below). `assets.run_worker_first` lists those two paths, so every game file is served straight from static assets without invoking the script. The game keeps working even if the script fails or runs out of free requests. From the project directory, run the following command. Wrangler asks you to sign in to Cloudflare the first time.

```sh
npx wrangler deploy
```

Add `--dry-run` to check the configuration without uploading anything. It should list the `EVENTS` Analytics Engine dataset and the `ASSETS` binding.

The repository can also be connected to Cloudflare with Workers Builds (Workers & Pages → Create → Import a repository). Cloudflare then reads `wrangler.jsonc` and redeploys on every push to `main`. The Worker's page lists its public address under Settings → Domains & Routes. Preview builds of other branches get no Analytics Engine dataset or secrets (the `previews` block is empty), so on a Preview URL events are accepted and dropped, and `/stats` shows its setup page.

## Visitor and play statistics

The game counts visits and play anonymously, so the owner can see how many people visit, when, from which countries, and what they play. There are two parts. Cloudflare Web Analytics, which is optional, counts page views. The game’s own events go to a Workers Analytics Engine dataset named `hibiscus_club_events`, and the private page at `/stats` shows them.

### What is collected

Each event stores the event name, a short detail from a fixed list, the character (`adult` or `little`), the game language (`en` or `es`), a count, the two-letter country Cloudflare derives for the request, and a coarse device class (`phone`, `tablet` or `desktop`). The Worker works out the device class from the browser’s User-Agent and then discards the User-Agent. Analytics Engine adds a timestamp. Purchases also store a price band.

Nothing else is stored or logged: no IP addresses, User-Agents, referrers, player-chosen names, cookies, local-storage identifiers, fingerprints, or any value that could link two visits by the same person. Visits are page loads, not people. The Worker rejects a request whole if it contains anything outside the lists below (`worker/events.js`), if it comes from another site, or if it is larger than 4 KB.

| Event | Detail | When |
| --- | --- | --- |
| `visit` | the room the page opened on | page load |
| `room` | `map`, `wardrobe`, `salon`, `booth`, `scrapbook`, `arcade`, `garden`, `runway`, `life` (any walk-in place), `house` | a room opens; moving between walk-in places is not counted again |
| `district` | `boardwalk`, `market`, `pavilion`, `beach`, `park` | a walk-in place is entered |
| `lang` | `en`, `es` | language switched |
| `character` | `adult`, `little` | character switched |
| `makeover` | `outfit`, `shoes`, `jewelry`, `hair`, `hair-color`, `makeup`, `nails`, `accessory` | something she owns is put on (counted per category, sent with a count) |
| `tryon` | the same categories, and `decor` | a locked option is tried on, or a paid Dream House piece previewed (counted like `makeover`) |
| `purchase` | the same categories and `decor`, plus price band `1-9`, `10-19` or `20-plus` | each option or Dream House piece bought |
| `surprise` | `wardrobe`, `salon`, `house` | Surprise me! |
| `favorite` | `saved`, `worn` | a favorite look is saved or worn |
| `game-start`, `game-done` | `memory`, `bouquet`, `runway` | first card, first flower or rehearsal start; win |
| `chat` | `boardwalk`, `market`, `pavilion` | she walks up to a resident |
| `errand` | `story-1` to `story-4` | a story is finished (each character has her own four; the character field tells them apart) |
| `daily` | `deliver`, `find`, `greet`, `compliment`, `tidy` | a daily errand is finished (the template, never its details) |
| `findable` | `boardwalk`, `market`, `pavilion` | a hidden treasure is picked up |
| `tutorial` | `done`, `skipped` | the first-visit tour of a walk-in place ends |
| `name` | `yes`, `no` | a name is set, or the first name prompt is skipped. The name itself is never sent. |
| `photo` | `studio`, `boardwalk`, `market`, `pavilion` (the scenery), `house` | a postcard or a Dream House room photo is taken |
| `decor-room` | `bedroom`, `kitchen`, `living`, `bathroom`, `playroom`, `patio` | a room of the Dream House is opened |
| `decor-place` | `bedroom`, `kitchen`, `living`, `bathroom`, `playroom`, `patio`, `walls`, `floor` (the collection the piece comes from) | a piece is placed (counted like `makeover`; never its position) |
| `decor-done` | the six rooms | a room is furnished for the first time |
| `decor-goal` | `bed`, `wall`, `rug`, `paint`, `top`, `friend`, `photo` | a room-tour goal is met |
| `challenge` | the brief: `picnic`, `disco`, `seashell`, `mall`, `rosy`, `midnight`, `homecoming`, `bob` | a style challenge is completed |
| `postcard` | `png` | a postcard is downloaded |
| `sound`, `sparkle` | `on`, `off` | the top-bar toggles |

`dist/analytics.js` checks every event against the same lists, adds up makeover and try-on changes, and sends batches with `navigator.sendBeacon` (or `fetch` with `keepalive`) when the page is hidden or every 20 seconds. Sending never delays the game, and a failed request is dropped. Nothing is sent from `localhost`, `127.0.0.1` or a `file:` page, when the browser sends Global Privacy Control or Do Not Track, or when the player turns sharing off. A small **Privacy** link at the bottom of every page opens a dialog that explains this in plain words in both languages and has the on/off switch. The island guide (**How to play**) points to it. The switch is saved with the game as `state.analytics` and is on by default.

To add an event, add it to `SCHEMA` in both `worker/events.js` and `dist/analytics.js`, call `track('event','detail')` in the game, and run the tests. The tests fail if the two lists differ or if the game uses a name that is not listed.

Analytics Engine keeps events for three months. It is available on the Workers Free plan (100,000 data points written and 10,000 read queries a day). The dataset is created on the first write. Each `/stats` page view runs three read queries.

### Set up the stats page

1. Create an API token: My Profile → API Tokens → Create Token → Create Custom Token. Give it one permission, **Account → Account Analytics → Read**, limited to your account.
2. In Workers & Pages → hibiscus-club → Settings → Variables and Secrets, add three variables of type **Secret**:
   - `STATS_KEY`: a long random password of at least 16 characters, for example from `openssl rand -base64 24`
   - `CF_ACCOUNT_ID`: your account ID (shown on the Workers & Pages overview)
   - `CF_API_TOKEN`: the token from step 1

   Alternatively, run `npx wrangler secret put STATS_KEY` (and the same for the other two). Never put them in `wrangler.jsonc`.
3. Open `https://<your worker address>/stats` and enter the stats key. A private cookie (HttpOnly, Secure, SameSite=Strict, limited to `/stats`) keeps you signed in for seven days. It holds a signed expiry, not the key. **Sign out** removes it. Changing `STATS_KEY` signs everyone out.

Until all three secrets are set, `/stats` shows these steps and no data. The page shows visits per day (per hour for 24 hours), top countries, devices, the game language, rooms, mini-game starts against completions, makeover changes and try-ons by category, purchases by category and price band, the Dream House (rooms opened and furnished, pieces placed by collection, Surprise me!, room photos, previews, room-tour goals), postcards, challenges, favorites, Surprise me!, walk-in places (trips, conversations, treasures), stories and daily errands, the first-visit tour and name prompt, and settings, for 24 hours, 7 days, 30 days or 90 days. It is server-rendered, makes no third-party requests and is marked `noindex`. Analytics Engine may sample busy events. Every stored row stands for `_sample_interval` real events, so the page counts `SUM(_sample_interval * double1)` and says so when any figure is an estimate.

### Cloudflare Web Analytics (optional)

1. In the Cloudflare dashboard, open Web Analytics → Add a site, and enter the game’s hostname (for example `hibiscus-club.<your-subdomain>.workers.dev`).
2. In Manage site, copy the `token` value from the JS snippet. It is 32 hexadecimal characters.
3. In `dist/index.html`, paste it between the quotes of `<meta name="cf-web-analytics-token" content="">` in the `<head>`, then deploy.

`analytics.js` loads Cloudflare’s beacon only when that token is present, and under the same rules as the game’s events: not on a local address, not with Global Privacy Control or Do Not Track, and not when the player turned sharing off. Turning the switch off takes effect for the beacon at the next page load. The beacon follows single-page navigation automatically. Room changes are also counted by the game’s own `room` events.

### Run it locally

`node serve.cjs` plays the whole game with statistics silently off. To exercise the Worker, run `npx wrangler dev --port 8790` and open `http://localhost:8790`. To try `/stats`, put test values for the three secrets in a `.dev.vars` file next to `wrangler.jsonc` (it is git-ignored). Locally, Analytics Engine writes are discarded, and the stats page calls the real SQL API with whatever account and token you give it. The browser side stays off on `localhost`, so test it under another hostname. Run `node --test` to check the event lists, validation and translation keys.

### Turn it off

- One player: the switch in the **Privacy** dialog (link at the bottom of every page), Global Privacy Control, or Do Not Track.
- Web Analytics: empty the token in `index.html`, or remove the site in the dashboard.
- Everything: remove `main`, `binding`, `run_worker_first` and `analytics_engine_datasets` from `wrangler.jsonc` to return to an assets-only Worker. The game then sends to a missing `/api/e`, which is harmless. Alternatively, also remove the `analytics.js` script tag from `index.html`. Delete the secrets and the API token when you no longer need them.

## A first trip around the island

1. Pick **Grown-up** or **Little Me** on the player card. Each character remembers her own look, name and adventure. The card shows where she is and her next step, with **Start the adventure** (later **Continue the adventure**) to go straight there. **Give her a name** (later **Change name**) is on the card too.
2. The map has two kinds of pins. Round icons are **rooms**; picture bubbles of a scene are **walk-in places** (Pearl Boardwalk, Flower Market, Starlight Pavilion, Sunny Cove, Breezy Park). The yellow **Next step** bar under the map and a **★ Next** flag on a pin show where to go. On a narrow screen the pins show only their icons; hover or focus a pin to see its name, and the passport under the map lists every place by kind.
3. Open **Dress-Up Studio**. The tabs hold **Outfits**, **Shoes**, **Jewelry** (earrings and necklaces) and **Scenery**. Choose a card to put it on. The selected item’s color swatches appear under the rack. The stage zooms in on the part you are styling. **Front**, **Left**, **Right** and **Back** under the stage turn her around in whatever she is wearing.
4. Visit the **Beauty Salon** for **Hair** (style and color), **Makeup** (lips, blush, eyeshadow and face gems), **Nails** and **Accessories** (clips and bows). Little Me sees only the options made for her age, so she has no Nails tab or eyeshadow.
5. Tap **Surprise me!** in either room for a random look built from what you own, usually around one color family. **Save look** keeps up to six favorite looks per character. Tap a favorite to wear it again, or tap its × to remove it after a confirmation.
6. From the studio or salon, choose **Walk the island runway** to rehearse. Watch the three marks, then repeat them in order. **Replay cues** repeats the same routine.
7. In the **Photo Booth**, choose scenery, a frame, and a corner sticker, then take a photo. The style challenge card lists exactly what to wear, ticks off what she already has on, and links to the right room and tab. A successful photo advances the challenge.
8. Open **Scrapbook** to download a 640 × 860 PNG. The album holds 24 postcards. Removing a postcard asks for confirmation and frees one space. Download favorites before clearing browser data.

Use a mouse or touch, or Tab and Shift+Tab to move between controls. Enter activates links and buttons. Space also activates buttons. In the studio and salon, the arrow keys move between tabs. Escape closes dialogs. Sound starts on: an endless, cheerful background tune begins with your first click or key press and keeps playing as you move between rooms, with sparkles for clicks and a fanfare for wins. The speaker in the top bar turns the music and sound effects off or on together, and the game remembers your choice.

## English and Spanish

The whole game is bilingual. **EN | ES** in the top bar (and in the island guide) switches every screen, dialog, announcement, item name and new postcard caption at once, without reloading or losing the current room, try-on or game round. The choice is saved with the game. With no saved choice, the game starts in Spanish when the browser's preferred language begins with `es`, and in English otherwise. Player-chosen names are never translated. In Spanish, Grown-up is **Yo Grande** and Little Me is **Yo Chiquita**.

## Walk-in places

Choose a picture-bubble pin on the map, or **Go to …** on the Next step bar. Each place has its own address (`#boardwalk`, `#market`, `#pavilion`, `#beach`, `#park`), so it can be shared and the Back button works. The old `#life` link opens the place where she last was. Click or tap the ground to walk; she walks there step by step, seen from the side when she crosses the scene, from the front or the back when she comes toward you or walks away, and faces you when she stops. Residents breathe, blink and move their lips while they talk to her. A second click redirects her. You can also focus the scene and use the arrow keys, or Tab to a resident, object or treasure and press Enter. The strip under the scene goes back to the **Island map** or to any other place in one tap.

The first time each character arrives without a name, a friendly dialog offers six names to pick with one tap, a box to type her own, and **Not now**. It is never asked again; **Change name** in the scene header and on the player card is always there. Names are cleaned the same way as before (control characters removed, 24 characters at most) and are never sent anywhere. Residents greet her by name and sometimes mention it in their small talk.

The first visit also shows a three-tip tour (how to walk, what the ★ marker means, where the next step and journal are). It moves on by itself as she does each thing, can be skipped at any time, and is remembered in the save.

**Always know what to do.** The yellow bar over the scene shows the next step in one line ("Pick a striped shell from the basket"), who or what it is at, and, when it is in another place, **Go to …** to travel there. Over the right resident or object a ★ with the word **Next** bobs; a smaller **!** with **Task** marks anything else to do there (a daily errand). With reduced motion or the sparkle button off, the markers stand still and the target's name tag gets a thick ring, so neither motion nor colour alone carries them. **Today x/3 · ✦ y/6** on the bar opens the **Journal**, which lists every story (done, in progress and coming up) and today's errands, treasures and bag. When a step or story is done, the conversation celebrates (confetti and fanfare) and shows the next step with a button to go there; the same news is announced once through the live region.

Mara collects shells on Pearl Boardwalk, Rosa tends the Flower Market, Kit runs the Starlight Pavilion, Sol is the lifeguard at Sunny Cove (Rincón Soleado), with a sandcastle kit by her towel, and Teo, a grandpa gardener, keeps Breezy Park (Parque de la Brisa) and its fountain, flower beds and kite stand. Ask about their work to become friends; after that, **What's new?** brings rotating small talk (eight lines each, plus a few about her name or the outfit she has on), which changes from visit to visit and day to day.

**Stories.** Each character has her own six stories, one at a time and in order, offered by a resident with a ★ **Can I lend a hand?** button:

**Every day.** Each real-world day (local midnight to midnight) each character gets three short errands, chosen from five templates and worth a few stars each: deliver something from one resident to another (4), find three hidden things in one place (3), say hi to three named residents (3), pay a resident a compliment (2) and tidy a resident's stall (2), spread over all five places. Six treasures (shells, petals, fallen stars, sand dollars or four-leaf clovers, at least one in each place, 1 star each) also sparkle on the ground. The set is worked out from the date and the character, so a reload never rerolls it and the two characters have different sets. When all three are done, the bar and journal say so and when new ones arrive. If the computer's clock is turned back to an earlier day, the latest day played stays in place until the clock catches up, so errands are never refilled that way.

**Take a scenic postcard** uses your current location in the photo booth (in the first three places; a saved look's scenery is limited to the studio and those three by `catalog.js`, so Sunny Cove and Breezy Park have no postcard button yet). The studio and booth also let you select any district or the original pink studio. Saved postcards retain the scenery you chose.

## The Dream House

Tap the house pin on the hill (or go to `#house`). Six empty rooms wait to be decorated from scratch: **Bedroom**, **Kitchen**, **Living Room**, **Bathroom**, **Playroom** and **Patio**. The row of room cards at the top shows a live miniature of each room; tap one to decorate it.

- **Furnish.** The tabs hold **This room** (the room's own furniture), **Other rooms** (everything else, with a filter by room), **Wall decor**, **Floor decor** (rugs, pets, plants and party things), **Paint & floors** and **Friends**. Tap a card to add the piece to a free spot, or drag the card onto the room (on a phone, hold the card a moment, then drag). Big furniture goes against the back wall, wall decor onto the wall, rugs flat on the floor under everything.
- **Arrange.** Drag a piece to move it; it stays under your finger or pointer. Standing pieces keep their feet on the floor, get a little smaller further back, and are drawn in depth order, so a chair in front of a table overlaps it. Wall pieces stay on the wall and rugs on the floor. Small things (lamps, the fruit bowl, the toaster, the rubber duck, the disco ball…) can stand on the floor or sit on a table, counter or shelf: drop them on top, and they ride along when the table moves. The selected piece has a × to remove it and a corner handle to resize it, and the toolbar under the room has **Flip** (only for pieces whose art can be mirrored), **Smaller**, **Bigger** (50 % to 180 %), **Back**, **Forward**, **Copy**, **Remove**, **Undo** and **Redo**. A room holds up to 40 pieces.
- **Painted rooms.** Every room comes in three painted looks (a bedroom with rose vine stripes and an arched window, one with lilac roses and white panelling, one with mint walls, ribbon garlands and a door, and so on; the patio is an outdoor terrace under a bougainvillea pergola, a jasmine porch with a green trellis or a sunny garden wall, each with a garden arch), all drawn at human scale, so a wardrobe stands just under the door and the Grown-up's head stays below its top, shown as small pictures at the top of **Paint & floors**. A room you have never decorated starts in its first painted look; rooms decorated before keep what they had. Switching looks, or going from a painted look to your own paint and floor and back, carries every piece along to the same place in the new room (Undo goes back). Each painted room has its own floor, size and perspective: furniture stands on its floor and against its walls, gets smaller toward its back wall as its floor does, wall decor keeps off its windows and doors (only bunting may cross above them, and a decor window never covers a painted one), rugs lie flat inside the floor, and Surprise me stands the main piece beside the windows and doors and keeps a walkway to every door.
- **Walls and floors.** Indoors there are six paints (blush, lilac, mint, butter, sky, peach) and six wallpapers (candy stripes, mint stripes, polka dots, gingham, little florals, paneled), and three woods, three tiles and two carpets. The patio is outdoors under a sky: pink or mint cottage siding, a flower trellis or a bamboo fence, on a lawn, a wooden deck, garden stones or beach sand.
- **Friends.** Invite the Grown-up and Little Me into any room. Each stands on the floor like a piece of furniture and wears the look she has on (never a try-on); change her outfit in the studio and she wears the new one when you come back.
- **Surprise me!** furnishes the room you are in from what you own: the room's own furniture along the back wall, a seating or play arrangement in the middle, a rug, small things at the front, a few things on the wall and something on a tabletop. It keeps your friends, and **Undo** brings back the room you had. **Start over** empties the room and returns it to its first painted look after a confirmation (Undo works here too).
- **Room photo** downloads a PNG of the room (with your friends if they are there) in the striped postcard frame, and adds it to the Scrapbook (if the 24 spaces are full it only downloads, and says so). Room photos in the Scrapbook can be downloaded again and removed like postcards.
- **Keyboard.** Every action works without a mouse. Choose a piece in the **In this room** list (or focus the room and press N or P to pick the next or previous one); then the arrow keys move it (Shift for bigger steps), + and − resize, F flips, Page Up and Page Down bring it forward or send it back, D copies, Delete removes, Ctrl+Z undoes and Ctrl+Y redoes, Escape lets go. Changes are announced. The arrow keys move between the tabs.

Most of the 96 pieces are free. Ten showpieces cost stars from the shared wallet: Dreamy Canopy Bed 20, Cozy Fireplace 15, Dream Dollhouse 15, Fishy Aquarium 15, Rainbow Ball Pit 12, Splash Pool 12, Hideaway Teepee 12, Striped Porch Swing 12, Disco Ball 10 and Heart Mirror 8 (131 together). A locked card shows its price; tapping it puts the piece in the room as a preview with **Buy** and **Put back** under the room. Buying asks for confirmation and then the piece is yours for every room. A preview is never saved, never appears in a room photo, and goes back to the shop when you switch rooms or leave the house.

**Rewards.** The first time each room is furnished (six pieces, three of them from the room's own collection) it pays 5 stars, 30 for the house. The **Room tour** card lists seven little goals, each paid once: tuck in a bed (3), hang something on a wall (3), roll out a rug (3), pick new paint or a new floor (2), set something on a table or shelf (3), invite someone over (3) and take a room photo (3), 20 in all.

## How the game was built

The original project supplied a page shell, a flower emblem, and an icon library. The finished game uses HTML, CSS, and browser JavaScript with no build step or dependencies. Every script shares the page’s global scope, in the order `index.html` loads them. A URL hash identifies each room, so links, refresh, and the browser’s Back button work with static hosting.

Each character is a layered paper doll with four views: front, left, right and back. A bald base doll picture per age and view sits under transparent sprites for the outfit, shoes, hairstyle, jewelry and hair accessories. The catalog stores a fit for every item on every doll and view. Outfits are warped row by row to the body, long sleeves are placed along the arms, and in side views the near arm is cut from the base and drawn over the outfit. The base dolls wear a lilac bodysuit, which is repainted in skin tone wherever an outfit would let it show, and an outfit is always drawn. The hairstyles were painted directly on these bald heads, in all four views, and then cut out, so each one is placed from its art rather than fitted by eye: `art/fit_hair_pack2.py` registers every worn proof (the hair shown on the head, `art/proofs/pack2/`) onto the game's base doll by matching the face, ears, jaw and neck that the hair leaves bare, and writes where each sprite sits in `dist/hair-fit.js`. A few corrections judged against the proofs (which parts hang behind the shoulders, where clips sit, which styles cover the ears) are in `HAIR_TUNE` in `catalog.js`, and `art/lab.html?sheet=proofs` shows every style on her head next to its proof. Each doll has her own list of hairstyles (`HAIR_STYLES` in `catalog.js`): the Grown-up has nine adult styles and Little Me nine toddler styles. Shoes are layered around the foot: the sole and insole sit behind it, straps and closed parts in front, and the bare foot is lifted onto a heeled or platform footbed and trimmed to the shoe's outline, so toes, polish and the top of the foot show through sandals and mary janes and no heel or ankle pokes out in any view. Side and back view art loads only when a view is first used. Makeup, nail polish, hair color and colorways are pixel recolors done once and cached. Hair colors, the default espresso included, are gradient maps over the style's own brightness range, so each color looks the same on every style and view. `composeDoll()` builds a dressed doll on one transparent canvas. The player card, studio, salon, booth, runway, walk-in place walker, favorites and postcards all draw from it. A saved postcard records the character and every look choice, so the renderer recreates it for display and PNG export. The artwork is AI-generated. The dolls and wearables arrived as sheets: a four-view turnaround of each base doll, front-view sheets of the outfits, hair, shoes and jewelry, and four-view sheets of the same items. `art/slice.py` and `art/slice_views.py` cut the sheets into trimmed sprites by following the alpha channel, clean the edges, and write a manifest of sizes and parts. `art/crop_dolls.py` crops the base figures onto a shared foot baseline. `art/fit_views.py` generates the side and back outfit warps, and `art/lab.html` renders contact sheets of every item on every doll, which is how the fits were tuned by eye. The source sheets are kept in `art/source/` and are not deployed.

The music is synthesized live in the browser by `dist/music.js` with the Web Audio API. There are no audio files or samples. An original tune in C major at 118 beats per minute is written as note strings, one character per sixteenth note, and arranged in six sections (sparkle intro, verse, chorus, second verse, bridge, second chorus) that make a 44-bar cycle of about 90 seconds and repeat for as long as the game is open. A look-ahead scheduler wakes every 25 ms and queues the notes for the next 160 ms on the audio clock, so timing stays steady. Bell lead, plucked chords, pad, bass, kick, clap, hat and shaker are built from oscillators and filtered noise, and pass through a delay, a generated reverb, a compressor and a limiter. Click sparkles and the win fanfare use the same audio context and output chain. Browsers require a user gesture before audio, so the music fades in on the first click or key press. It pauses while the tab is hidden, and the speaker button fades everything out and remembers the choice.

The island map and the five district pictures are still paintings, brought to life by `dist/scene-fx.js`. It draws the picture through WebGL with three.js at exactly the framing the page would use, so the pins and the walking character stay aligned on top. `dist/scene-data.js` marks regions of each picture (water, surf, waterfalls, palms, flower beds, lanterns, sky) and how each moves: water refracts and glints and ripples where you click, plants sway from their base, lights glow and flicker, clouds drift, the sailboat bobs, and petals, butterflies, gulls or fireflies drift through. three.js is stored in `dist/vendor/three/` and is fetched only when one of these scenes is shown. With the sparkle button off, the reduced-motion setting on, or no WebGL, the plain picture is shown instead.

The dolls and the five residents are cut-out puppets brought to life with the same three.js, by `dist/puppet.js` with the data and animation math in `dist/puppet-rig.js` (see **Living characters** below). They breathe, blink, talk, smile, laugh, wave, cheer and walk.

`dist/fx.js` draws the glitter pointer trail, click bursts and win confetti on one overlay canvas that ignores pointer input. Its animation loop stops when no particles are left. The sparkle button in the top bar turns the effects off, and the reduced-motion setting replaces them with a brief still sparkle.

The island is an original AI-generated illustration with eleven HTML links positioned over it: six round icon pins on the buildings and the hilltop (rooms) and five photo-bubble pins on the dock, the flower beds, the bridge, the south-west sand (Sunny Cove) and the green east of the salon (Breezy Park) (walk-in places). On narrow maps Sunny Cove's floating label sits beside its pin, since the pin is near the bottom edge. The gingham, paper frames, stamps, and game controls are drawn with CSS and vector icons.

The Dream House draws each room on two stacked canvases: the empty room, painted once per wall and floor choice at its full 1536 × 1152 size and scaled by CSS, and the pieces, redrawn in one `requestAnimationFrame` only when something changed. Dragging updates one position per frame and touches no other element, so 40 pieces stay smooth (in headless Chromium a drag with 40 pieces runs at a steady 16.7 ms per frame). Pieces are picked by their painted pixels (a small alpha mask per sprite), not their boxes. The room is a dollhouse cutaway in a gentle one-point perspective (lines along the room's depth meet far above it), and `decor-logic.js` holds its geometry: the back wall from x 150 to 1386 down to y 640, the floor widening to the front edge at y 1108, the frame around it. A standing piece is positioned by the point where it touches the floor (the manifest's `anchor`), sized by its `defaultScale` and by its depth, and drawn in depth order of that point; rugs come before everything that stands, wall pieces before both, and a piece on a tabletop right after its table. Furniture is drawn in 3/4 view, so every standing piece has a footprint, not a point: its front contact (the manifest anchor), its rear feet (a per-item depth in `ground` in `decor-data.js`, read by eye from the sprites) and its left and right contact (the manifest footprint band). The whole footprint must lie on the floor, so a deep piece pushed against the back wall stands lower, with its rear feet on the wall line; rugs lie wholly on the floor, and wall pieces stay between the crown moulding and the skirting board (shrinking to fit the patio's low garden wall). Every piece is grounded by its shading: a soft pool of shade over its footprint, its base laid flat toward the lower right (the art is lit from the upper left), a dark contact right at the feet, a faint shadow on the back wall for tall pieces standing against it, a drop shadow for wall pieces and an edge shadow for rugs. These shadows are blurred silhouettes made once per sprite. Only the sprites of pieces in the room in view are downloaded; the picker uses the 128 px thumbnails with lazy loading, and the room cards draw their miniatures from the same thumbnails. None of the decorator's scripts, its stylesheet, the manifest or a sprite is requested anywhere else in the game: `game.js` loads them the first time the house (or a room photo in the Scrapbook) is shown.

**Adding furniture.** Put the sprite in `dist/assets/decor/<room>/<id>.webp` and a 128 px thumbnail in `dist/assets/decor/thumbs/<id>.webp`, and add its entry (id, room, English and Spanish name, `placement`, `anchor`, `defaultScale`, `mirror`, `footprint`) to `dist/assets/decor/manifest.json`; `art/slice_decor.py` writes all of this when it slices a sheet. That is enough for it to appear in the picker. In `dist/decor-data.js`, give a standing piece its depth in `ground` (how far above the front contact its rear feet are, as a fraction of the sprite's height; 0.1 if unlisted). Optionally, give it a price in `prices`, a tabletop in `surfaces` (where small pieces can sit on it), and a place in a room's `recipes` for Surprise me. `node --test test/*.mjs` checks that every id named in `decor-data.js` exists.

**Painted rooms.** The eighteen painted empty rooms (`art/source/round2/rooms/room-<room>-<1|2|3>.webp`, ten at 2386 × 1792 and eight at 1151 × 864) are drawn instead of the procedural room when chosen. Each painting has its own geometry, so the decorator does not assume the procedural layout: every function in `decor-logic.js` that places or measures a piece takes a *where* argument, the room id for the procedural room or the backdrop id for a painted one, and `DecorLogic.geo(where)` gives that room's geometry. For a painted room it comes from the backdrop's entry in `DECOR.backdrops`:

- `floor`: the floor quadrilateral (back-left, back-right, front-right, front-left; the front corners may lie outside the picture). Standing pieces keep their whole footprint inside it: rear feet never above the back floor line, sides inside the side walls as they converge toward the back.
- `vp` and `scale`: the vanishing point and the furniture scale at the back wall (1 = the manifest's 280 px per metre). A piece at floor y is scaled by `scale × (y − vp.y) / (backY − vp.y)` (one-point perspective, so pieces shrink toward the back in proportion to that painting's floor), but grows to at most 1.5 times its back-wall size at the front (the paintings grow about 1.55 times to their front edge). Nothing stands closer than 24 px to the picture's front edge, and rugs end 30 px before it. Rugs are also squashed vertically (the painted floors are seen from lower down) and drawn in thin bands, each as wide as the floor's scale at its depth. A piece deeper than a shallow painted floor (a big bed at 180 %) is made smaller to fit.
- `wall`: zones for wall decor, `openings`: windows, doors and arches (wall pieces keep off them unless `DECOR.overOpenings` lets that piece cross that kind (only the bunting); `DECOR.decorWindows` never cover one, and Surprise me leaves them out of a painted room with windows or doors of its own; on a patio a `hang` zone is a pergola beam that only `DECOR.hangers` hang from), `skirt`, `rail` and `ceil` lines, `clear`: floor kept free in front of doors (Surprise me and tap-to-add avoid it), `light`: which way contact shadows lean.

Painted rooms are measured, not typed: `python3 -I art/build_rooms.py` trims each painting to exactly 4:3 (a row or two of ceiling) and writes the 1536 × 1152 backdrop (WebP q80, 74 to 325 KB, 2.60 MB for all 18; the eight small paintings are enlarged 1.33 times with Lanczos and a light unsharp mask, and hold up next to the large ones at the stage's size) and a 192 × 144 thumbnail (2 to 7 KB, 58 KB in all) to `dist/assets/decor/rooms/`; `--grid DIR` writes copies with a labelled 50 px grid. `python3 -I art/measure_rooms.py` then refines rough hints read off that grid on the picture itself (the back floor line and the back corners by the strongest edges, the vanishing point by a joint search for the two lines through the back corners that run along the strongest edges, i.e. the side walls' skirting, or the patios' balustrade bases, meeting the floor), takes the scale straight from a yardstick in the picture (the door opening, 2.0 m, in the rooms with a door; the garden arch, 2.0 m, on the patios; the ceiling line, 2.5 m, in the window rooms, whose sills came out at about 0.6 m instead of the 0.9 m asked for), prints the back wall's width and the door, ceiling and sill heights it implies as a check, and writes the generated block in `decor-data.js`; `--overlay DIR` writes each backdrop with its floor, wall zones, openings, keep-clear areas, vanishing point and a 1.7 m figure (the Grown-up) drawn on it for checking by eye. All eighteen were drawn on one shared layout: the back wall from x 300 to 1232 and from the ceiling line at y 250 down to the floor at y 902, so every room's scale is 0.91 to 0.98 (about 255 to 275 px per metre at the back wall) and its back wall about 3.5 m wide. **To add a painted room**, put the painting in the source folder, add its rough hints to `HINTS` in `art/measure_rooms.py`, run both scripts, check the overlay, and name it as `house.scheme.<id>` in both dictionaries; the first scheme of a room is the look a new room starts with. Only the current room's backdrop is downloaded (and a room photo's, when the Scrapbook draws one); the room cards and the picker use the thumbnails.

## Living characters

The dolls move as cut-out puppets built from their still pictures, so every outfit, hairstyle, colour and piece of makeup moves with them without new art.

**Layers.** `composeDoll()` in `portrait.js` runs an ordered list of draw operations; `composeDollLayers(shot, view)` runs the same operations each on its own canvas and returns them as aligned layers (hair behind, outfit behind, shoes behind, body, gem, shoes, outfit, near arm, sleeves over it, necklace, earrings, hair shadow, hair in front, clips), all in the coordinates of the 600 × 1060 doll canvas. Drawing the layers in order gives the still picture; `composeDoll` itself draws exactly what it drew before, so postcards and PNGs are unchanged (a test page compared 72 renders pixel for pixel). Side views also return the near and far shoe apart. Nothing new is cached there; the puppet keeps what it needs.

**Rig.** `puppet-rig.js` measures, per doll and view, a skeleton (root, hips, spine, chest, neck, head, hair, two arms of shoulder, elbow and hand, two legs of hip, knee and foot, two skirt bones), stored in doll-local pixels and exposed in normalized doll-canvas coordinates (`HibiscusPuppetRig.rig(doll, view).joints`), plus where the arms and legs are cut from the body, where a skirt starts and the face landmarks (eyes, the line where the mouth opens, its corners, cheeks, chin). The right view is the left view mirrored. In side views the far arm and leg are shaded copies of the near ones, drawn behind the body and faded in as the limbs part; the far shoe follows the far foot.

**Pieces and skinning.** `puppet.js` cuts each layer into pieces by those regions: torso, head (a fine mesh for the face), each leg, each arm, and for skirts and dresses (`OUTFIT_KIND`) the skirt below its line (trousers, shorts and pyjamas follow the legs instead; a jacket or cardigan can move the line with `SKIRT_TOP`). How an arm meets the body depends on the sleeves (`SLEEVES` in `puppet-rig.js`): a bare arm is a ball joint (round the shoulder only a disc about the joint, which the torso also keeps underneath, so a raised arm never opens a gap); puffed and tee sleeves stay on the shoulder and the arm comes out from under them; long sleeves, jackets and cardigans bend smoothly at the shoulder and the whole sleeve follows the arm. Flared skirts stay over the hands as in the still. In side views the body under the near arm is filled from the fabric beside it, and the torso keeps the top of the thigh, so a swinging arm or leg never opens a hole. Each piece is a textured grid; every vertex carries a chain of up to eight (bone, fraction) pairs, and the vertex shader composes the bones' local transforms at those fractions, interpolating angles so a bent joint keeps its width. A hard rest-space mask gives every pixel to exactly one piece of its layer, so at rest the puppet is the still picture (a mean difference under 0.2 of 255 at full size) and no seam can show.

**Face.** Where drawn expression heads exist (below), they are what players see. Otherwise (Little Me in profile, and the residents) the face is procedural: the head mesh has two rows on the mouth line; a displacement basis opens the jaw below it (the corners stay closed), lifts the corners and cheeks for a smile and narrows the eyes. An overlay canvas draws the eyelids (skin sampled above each eye, eyeshadow included, smoothed, with a soft lash line that thickens to the outer corner) and the inside of the open mouth (Grown-up: under her upper teeth, with the edge of the lower teeth; Little Me: between her lips, with a tongue and no teeth), clipped to the face.

**Sol and Teo.** The two newer residents come from three full-body pictures each (neutral, talking, smiling; `art/source/pack2/06-island-places/resident-*`), normalized by `art/build_residents_pack2.py` to the same 176 × 432 frame and foot baseline as Mara (premultiplied downscale, so the edges carry no fringe). Their talking and smiling pictures register with the neutral one at shift 0, so instead of a drawn mouth `puppet.js` blends the lower face of `sol-talk.png` / `sol-smile.png` (and Teo's) inside a feathered ellipse round the mouth (`face.patch` and `frames` in `puppet-rig.js`): the open mouth fades in with each syllable and she smiles between words. Eyes, blinks, breathing and sway work as for the other residents, from landmarks measured on the neutral picture.

**Animation.** Pure functions of time and a per-character seed, blended: idle (breathing in the chest and shoulders, weight shift, an occasional head tilt, blinks every 2.4 to 6 seconds, sometimes doubled; the occasional glance is only used to pick the look-left and look-right drawn heads; the painted eyes do not move their irises), talk (syllable-like jaw motion with pauses and small nods), emotes (`smile`, `laugh`, `wave`, `cheer`, `sway`, `shy`, `pose`, `nod`) and the walk. `RAISED_ARM_EMOTES` in `puppet-rig.js` is off for now: the cut-out shoulders cannot yet show an upper arm lifted away from the body cleanly, so every outfit in every view plays arm-safe versions (`ARM_SAFE`): a wave is a friendly head tilt with a little bob and a big smile, a cheer is a happy wiggle (a bounce, a big open smile or laugh, hands low), a pose is a weight shift, head tilt and smile with the arms as at rest. No emote turns an upper arm more than `ARM_SAFE_MAX` (4 degrees); a test checks it. Arms still swing when walking. Turning the flag on brings back the full wave, cheer and hand-on-hip pose, with gentler variants for long and puffed sleeves (`GENTLE`). Side views: a gait with two-bone IK, heel strike and toe-off, opposite arm swing, a slight lean with the head kept level and the skirt flaring with the leading knee; the body travels exactly as far as each stance foot moves back, so feet do not slide (under 2 doll px, a fraction of a screen pixel), and the hips move 4 to 5 px on a 375 px leg. The pace (`paceFor`) blends `GAIT`, an easy stroll, into `GAIT_FAST`, a brisk slightly stylised walk with longer strides and quicker steps, by the length of the walk; at full stride the legs stretch slightly rather than the hips dropping. Front and back views: the legs foreshorten as they swing toward or away from the camera. Little Me toddles: shorter quicker steps, legs apart, arms out, bigger sways and curious head tilts. Hair and skirt follow through on springs. Turning between views squashes to the edge and opens in the new view.

**Where.** The walker (walk, idle, talking when she answers in a conversation, cheering when a story step or errand is done, a smile or a shy tilt for a treasure), Mara, Rosa, Kit, Sol and Teo in their scene and in the conversation's photo (breathing, a small sway, blinking and talking while their line shows), the studio and salon stage (idle, a sway or smile when an item is put on, a cheer when it is bought, turning with Front / Left / Right / Back), the runway (she walks to each lit mark and strikes a pose, and cheers when the routine is won), the photo booth preview (idle) and the player card (a subtle idle). Saved postcards and PNGs are still pictures.

**Performance and fallbacks.** One WebGL context renders every puppet offscreen and copies it into the page's own canvas; at most four puppets live at once. They pause when off-screen, when the tab is hidden or when their canvas leaves the page, release unused GPU textures (a few recent looks stay warm, and room changes do not grow GPU memory), and lower their resolution when frames are slow. A look and view builds in about 0.3 to 0.5 s in the background while the still picture shows; the animation math costs about 0.01 ms a frame. three.js is fetched only when a puppet is created. With reduced motion, the sparkle button off, no WebGL2 or any failure, the still pictures and the old glide stay exactly as before; turning sparkles back on restarts the dolls. `?softgl` in the address lets puppets run on a software renderer, for automated checks.

**Drawn expressions.** The owner's expression sheets (`art/source/pack2/02-faces`, twelve heads each: neutral, soft smile, big smile, laugh, blink, half closed, talking eh, oh and ah, surprised, look left, look right) are made game-ready by `python3 art/build_faces.py` (Pillow and numpy; `--check <dir>` writes registration difference images and previews). It registers every head to the base doll's head (scale and offset from the skull and ear outline, refined on the eyes, nose and mouth), matches the lighting with a smooth skin-only ratio map so no patch shows, keeps only the part of the face each expression needs (`EXPRESSION_REGION`: the eyes for blinks and glances, the mouth and chin for talking, the face interior from brows to chin for laugh, surprise and smiles, so hair, ears, earrings, the outline and the neck stay the live doll's), finds each head's lips, and writes `dist/assets/faces/faces-<doll>-<front|side>.webp` (colour and blend mask, about 70 to 110 KB) and `…-lips.webp`, in doll pixels at 2×. `EXPRESSION_ART` in `puppet-rig.js` lists them (file, lips, doll-local `at`, `cell`, `scale`); a new sheet is its files and one entry. In the game every drawn expression is laid over the bare base head and then the player's makeup is painted again (`applyFaceMakeup` in `portrait.js`: lipstick on the drawn lips, eyeshadow on a closed lid, blush), and the result replaces the live head only inside its region, so outside it the face is exactly the still picture. The rest pose stays the base face (the Grown-up's own open smile). Two channels cross-fade (`expressionTargets`): the eyes (blink and half closed in a quick ladder, glances) and the mouth (talking visemes chosen by how far the jaw opens, or a whole-face laugh or surprise, and Little Me's smiles), so she can blink while she talks; the Grown-up's smile stays her own. Little Me's side sheet is drawn in three-quarter view and cannot sit on her strict profile (a second cheek and nose show), so the build script leaves it out and her side views keep the procedural face. Face gems are their own layer and stay on top.

**Lab.** Serve the repository root and open `/art/puppet-lab.html` for both dolls and the residents in any view, look and animation, with a time slider; `window.lab` renders frames, contact sheets and the rest pose against the still (`lab.diff`).

## Translations (i18n)

`dist/i18n.js` loads before every other script and defines the global `I18N` and its shortcut `t(key, vars)`. Strings live in two dictionaries with identical keys, grouped by screen: `nav.*`, `map.*`, `card.*`, `challenge.*`, `booth.*`, `arcade.*`, `garden.*`, `scrapbook.*`, `tab.*`, `group.*`, `room.*`, `fav.*`, `shop.*`, `runway.*`, `quest.*` (next-step bar), `life.*` (walk-in places), `name.*`, `tour.*`, `district.<id>.*`, `story.<doll>.<n>.*`, `daily.*`, `chat.<district>.*` and `catalog.*`. Daily errand texts are whole sentences with the item, people and place as variables (for example `daily.deliver.todo`: “Pick up {item} from {from} for {to}” / “Ve con {from} a recoger {item} para {to}”); item names carry their own article in each language. English is in `i18n.js`, except the catalog display names, which stay next to their art in `catalog.js` and are registered at load as `catalog.item.<id>`, `catalog.tint.<slug of the English name>`, `catalog.hairColor.<id>` and `catalog.<lips|blush|shadow|gem|nails>.<id>`. Spanish is in `i18n-es.js`.

- `{name}` interpolates a variable. Numbers are formatted for the language. `{name|lc}` lower-cases the first letter, for a catalog name used mid-sentence.
- A plural entry is `{one:'…', other:'…'}` and is chosen by `vars.count`, for example `t('arcade.bestTurns', {count: 3})`.
- Write whole sentences with variables instead of joining fragments, so each language keeps its own word order.
- A key missing from Spanish falls back to English and logs one warning in the console on a local server. An unknown key renders as an empty string, never as the key.
- Static markup in `index.html` carries `data-i18n` (text), `data-i18n-html` (trusted dictionary markup) or `data-i18n-attr="aria-label:key;title:key"`.
- Data tables (places, districts, stories, catalog items) expose `name` and similar fields as getters, so cached lists read the current language. Changing language fires a `langchange` event. `game.js` then redraws the room in place, and open dialogs redraw their text.

To add a string, add the same key to both dictionaries and call `t('group.key', {vars})` where it is shown. To add a language, create `dist/i18n-<code>.js` with `I18N.add('<code>', {…})` holding every key, load it in `index.html` after `i18n.js`, add the code to `SUPPORTED` in `i18n.js`, and add a button with `data-lang="<code>"`, `lang` and the language's own name as its `aria-label` to both `.lang-switch` groups in `index.html`.

## Saves and compatibility

The game stores character looks, stars, stamps, challenge progress, delivered bouquets, best memory score, audio preference, and scrapbook in the browser’s `localStorage` under `hibiscus-club-v1`. `lang` holds the language the player picked (`en` or `es`), or `null` until the player chooses one. The shop adds `spent` (stars spent, while `stars` stays the lifetime total), `owned` (bought option keys such as `item:butterfly-clip`, `tint:gold-hoops:rose-gold`, `hair-color:lilac` or `lips:cherry`) and `favorites` (up to six looks per character). `analytics` is `false` when the player has turned off anonymous play counts (anything else counts as on). The island adventure adds `tutorial` (`done` or `skipped` once the first-visit tour is over), `dayMax` (the latest day the dailies were played, `YYYY-MM-DD`) and, in each character's `life` record, `quests` (her story stages), `credit`, `asked` (the name prompt was shown), `talks` (conversations per resident) and `daily` (`day`, `prog` per errand, and `found`, a bit mask of treasures). Stories added later go at the end of `quests`, so a save simply shows them as available (never paid again for what it finished). `daily` also has `v`, the version of the day's plan: a record without it was saved before Sunny Cove and Breezy Park opened, so that day keeps its three-place plan (and its progress) and the next day uses all five places. `stages`, the three shared story stages of older saves, is read once and migrated: the Grown-up keeps them as her first three stories, and Little Me's finished old stories become `credit` (6, 8 and 10 stars), which her new stories use up in order before paying out, so no star is lost or paid twice; her unfinished old story starts over as one of her own. Players who already had story progress or friendships skip the tour. Everything read back is validated. Older saves keep working: integer-style looks are mapped to the catalog, and anything a saved look or favorite already wears stays owned. Bought options that are free now stay in `owned` (stars spent are not refunded). A saved look, favorite or postcard in a hairstyle the character no longer has shows her default style (Beach Babe Waves for the Grown-up, Ringlet Pigtails for Little Me), keeping the hair color and everything else; the Grown-up's old kid styles fall back this way. Styles that were redrawn keep their ids, so old looks show the new art. An unfinished memory round, bouquet, or rehearsal lasts for the current page session. Leaving the runway ends that rehearsal.

The Dream House adds `house`: `{v:1, at, rooms, owned, done, goals}`. `at` is the room last decorated; `rooms` has one entry per room, `{w: wall, f: floor, b?: painted scheme, p: pieces}` (`b` is a backdrop id, or `''` when the player chose paint and flooring over the painted looks; a save without `b` keeps its paint and floor unless the room was never decorated, which starts in its first painted look; an unknown or other room's id falls back to the paint and floor), pieces stored in the coordinates of that room's look, and each piece is a short array `[id, x, y, scale %, flip 0|1, z?, host?]` in whole room pixels (`z` is the bring-forward/send-back step and `host` the index of the table a small piece sits on, both only when set). `owned` lists the paid pieces bought, `done` the rooms already rewarded as furnished and `goals` the room-tour goals paid. Six full rooms (240 pieces) take about 8 KB. `game.js` only checks the shape on load (an object under 64 KB); everything is validated when the house first opens: unknown ids, wall or floor names and rooms are dropped or reset to the room's defaults, numbers are clamped into the room, each room keeps at most 40 pieces and each character once, a paid piece that is not owned is dropped, and every piece is put back where its kind belongs. Previews are never written. A room photo in `photos` is a normal postcard entry with `kind: 'room'` and `room`, a small snapshot of the room (`{r, w, f, b?, p, looks}`; older snapshots without `b` are drawn in the procedural room as before) that is drawn again when the Scrapbook is shown; older saves have none, and an entry whose snapshot is not understood is shown as an ordinary postcard.

Each browser profile and site address has its own save. Using a different port gives you a separate game. Private browsing or clearing site data can erase progress. If the browser blocks storage, the current session remains playable. Exported PNGs remain wherever you downloaded them.

## Verification

The checks covered every tab and option type on both characters, with keyboard focus kept on the chosen option. They also covered trying on and leaving (reverted), trying on and buying (the balance drops and persists after a reload), refusing a purchase without enough stars, and Golden hour staying unlocked after spending. Surprise me was run hundreds of times, using owned options only. Favorites were saved, worn and removed. Three style challenges were completed, and a postcard PNG was downloaded. An old integer-format save was migrated with stars and photos. The runway and Island Life were checked for the current look. All rooms and tabs were checked for horizontal overflow at phone width, with no console errors. Every item was reviewed on contact sheets in all four views on both dolls. The music was checked to keep scheduling across room changes and to stop and restart cleanly from the speaker button. In each language, a scripted walk through every room, tab, dialog and mini-game looked for text left in the other language, and the two dictionaries were checked for matching keys and variables.
